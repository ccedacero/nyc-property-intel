## Security findings — tracked, NOT hastily patched

These are real but low real-world risk for a pre-revenue single-tenant product;
each is a transactional-auth change that deserves a focused, tested PR rather
than a rushed edit inside a broad sweep. Priority order:

- **▶ H-1 — signup abuse via spoofable client-IP + rotate-on-request.**
  `/api/chat/signup` has no per-email throttle and `_get_client_ip` trusts
  `Fastly-Client-IP`/`CF-Connecting-IP`/`X-Real-IP` from the request (Railway
  origin doesn't strip them), so the 3/IP/hr limit is bypassable with a rotating
  header. Because a returning-email signup *immediately* revokes the live token
  (rotate-on-request), an attacker who knows a customer's email can repeatedly
  kill their session and email-bomb them. **Also a self-inflicted UX bug:** the
  new sign-in-from-anywhere flow encourages re-signup, and any returning user
  with a live token loses their session the instant they submit the form.
  **Fix:** (a) rotate-on-*activate*, not on request — don't revoke the old
  token until the new link is clicked; (b) per-canonical-email throttle on
  signup; (c) trust client-IP headers only from the real CDN edge range.
- **▶ H-2 — account-enumeration oracle.** New email → `{token}`; returning email
  → `{ok:true}` (no token). The response reveals registration status. **Fix:**
  identical response body for both; drop or out-of-band the instant token.
- **▶ M-4 — instant token for an unverified email can read that email's
  watches.** Watches are creatable by email alone (no token), and the
  instant-token path issues an identity for a brand-new email with no ownership
  proof; that token can call `/api/watch/mine` to read a victim's watched
  buildings and unsubscribe them. **Fix:** don't key any read surface on an
  unverified email (require activation, or key watches on `owner_token_hash`
  like reports).
- **▶ M-5 — daily quota reset via re-signup.** Usage is keyed on `token_hash`;
  rotation issues a new hash, resetting the 10/day + 5-analyze caps. **Fix:**
  email-scope the counters.
- ▶ L-7 PII (emails/IPs) in app logs; ▶ L-11 body-size cap only reads
  Content-Length (chunked bypass). Both low.
